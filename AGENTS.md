- Bahasa/runtime: Python 3.12+.
- Entry point CLI: `main.py`.
- Entry point Telegram bot: `bot.py`.
- HTTP/Vercel entry point: `api/index.py`, Flask app `app`.
- Source: `app/`, `api/`; test directory belum tersedia.

## Lifecycle wajib

Pilih lifecycle sesuai ukuran perubahan:

```text
DEFINE → PLAN → BUILD → VERIFY → REVIEW → SHIP
```

- **DEFINE** — tetapkan tujuan, batasan, acceptance criteria, dan risiko.
- **PLAN** — baca kode relevan, petakan dependency, dan tentukan urutan implementasi.
- **BUILD** — implementasikan perubahan minimum mengikuti pola project.
- **VERIFY** — jalankan compile check, test yang tersedia, dan smoke test surface yang berubah.
- **REVIEW** — tinjau correctness, readability, architecture, security, performance, callsites, serta diff.
- **SHIP** — untuk deployment/migration, siapkan environment, observability, dan rollback.

### Gating

- Feature baru atau perubahan multi-file: DEFINE dan PLAN wajib sebelum BUILD.
- Perubahan perilaku atau bug fix: gunakan siklus RED → GREEN → REFACTOR bila surface dapat diuji.
- Setiap perubahan kode: VERIFY dan REVIEW wajib.
- Deployment, migration, atau release: SHIP wajib.
- Dokumentasi murni atau konfigurasi statis tanpa perubahan perilaku boleh memakai lifecycle ringan dengan verifikasi relevan.

## Trust boundary dan keamanan

- Validasi input di boundary Flask, Telegram, CLI, dan database.
- Endpoint cron wajib mempertahankan autentikasi `CRON_SECRET`; jangan mengubah authorization tanpa threat model.
- Gunakan Supabase service-role key hanya di server; jangan menaruhnya di client, fixture, atau source.
- Jangan mencatat nomor telepon, token, API key, credential, atau payload sensitif secara penuh.
- Pertahankan timeout dan error generik pada integrasi API eksternal.
- Query Supabase harus tetap terparameterisasi melalui API client/request yang aman.

# RENTRY MARKDOWN FORMATTING RULES (rentry.co COMPATIBILITY)

When generating responses, narratives, notes, summaries, or structured content, format everything using Rentry Markdown syntax (rentry.co) so that it looks clean, aesthetic, and is 100% copy-paste ready for Rentry:

- Structure &amp; Paragraphs: Single return starts a new line; double return (blank line) creates a distinct paragraph. Use `[TOC]` or `[TOC2]` at the top of structured or multi-chapter narratives.
- Headings &amp; Alignment: Use standard `# Header 1` up to `###### Header 6`. Use `-> Centered text <-` for titles/scene banners/dates and `-> Right-aligned ->` when appropriate. Also supports `### -> Centered Header <-`.
- Emphasis &amp; Highlights:
  - Bold: `**bold**`, Italics: `*italics*`, Strikeout: `~~strike~~`, Mark / Highlight: `==highlighted text==`
  - Spoilers: `!> Hidden spoiler text`
  - Colors: `%color% Colored Text %%` or `%#HEXCODE% Colored Hex Text %%` (e.g., `%red% text %%`, `%#ACBDEF% text %%`)
  - Underline &amp; Styles: `!~ Simple Underlined Text ~!`, `!~color; Underlined with color ~!`, `!~color;style; Underlined with style ~!`, `!~color;style;type;thickness; Full underline custom ~!` (e.g. `!~red;wavy; Wavy Red Underline ~!`, `%violet% !~green; Colored with Underline ~! %%`)
- Callouts &amp; Admonitions: Use Rentry admonition blocks for system notifications, NPC profiles, scene metadata, or important side notes:
  ```
  !!! note Title
      Indented text (4 spaces or 1 tab)
  !!! info Scene Metadata
      Details here...
  !!! warning Content Advisory
      Warning details...
  ```
- Tables: Format neat tables with aligned colons (`:---:` for center, `---:` for right). Support internal newlines with `\n`.
- Quotes &amp; Code: Use `> Quote` and `>> Nested quote`. Code blocks use triple backticks with language tags or single backticks for `inline code`.
- Rules &amp; Comments: Use `***` for horizontal dividers and `[//]: (Internal hidden comment)` for raw drafting notes.
